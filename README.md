# TeamMind — Интеллектуальный помощник для формирования рабочих команд

Кроссплатформенное десктопное и веб-приложение для анализа загрузки, отпусков, навыков и рабочих предпочтений сотрудников с целью автоматического подбора оптимальных и сбалансированных проектных команд.

---

## 🛠 Технологический стек

| Компонент | Технологии | Назначение |
| :--- | :--- | :--- |
| **Frontend** | React 18, TypeScript, Vite, Recharts, Lucide Icons | Современный интерфейс, интерактивные графики, конструктор команд |
| **Desktop** | Electron 33 (Secure Context Isolation, Preload API) | Настольная оболочка под Windows/macOS/Linux |
| **Backend** | Python 3.11+, Django 5.1, Django REST Framework | REST API, бизнес-логика, асинхронные потоки, роли и аутентификация |
| **GraphQL** | Strawberry GraphQL | Гибкие связанные выборки, мутации согласования (`/graphql/`) |
| **База данных** | PostgreSQL 16+ (с поддержкой SQLite3 для локальной разработки) | Хранение сущностей, связей и истории изменений |
| **DevOps & QA** | Docker Compose, Pytest, Pytest-Asyncio, Faker | Контейнеризация и автоматизированное тестирование |

## 📐 Математическая модель алгоритма подбора

Общий рейтинг каждого кандидата рассчитывается по формуле взвешенной многокритериальной оптимизации:

$$S = 0.35K + 0.25A + 0.20L + 0.10T + 0.10C$$

* **$K$ (35%) — Соответствие профессиональным навыкам:** сопоставление требуемых компетенций проекта с уровнями кандидатов ($1..5$), учет бонусов за уровень сеньорити и обязательных требований.
* **$A$ (25%) — Доступность и отсутствие отпусков:** анализ утвержденных отпусков в календаре. Если отпуск перекрывает проект, кандидат исключается или штрафуется.
* **$L$ (20%) — Баланс рабочей нагрузки:** процент текущей занятости на активных проектах. Кандидаты с нагрузкой $>85\%$ штрафуются для предотвращения выгорания.
* **$T$ (10%) — Совместимость расписаний и биоритмов:** сопоставление хронотипов (*«жаворонок»*, *«сова»*, *«промежуточный»*) и пересечение предпочтительных часов совместной работы.
* **$C$ (10%) — Предпочтения взаимодействия:** учет добровольных взаимных оценок совместимости и стилей работы (асинхронный/синхронный).

## 🚀 Быстрый запуск

### Вариант 1: Через Docker Compose (все сервисы в контейнерах)

```bash
docker compose up --build
```
* **Frontend:** [http://localhost](http://localhost)
* **Backend REST API:** [http://localhost:8000/api/](http://localhost:8000/api/)
* **GraphQL:** [http://localhost:8000/graphql/](http://localhost:8000/graphql/)
* **Django Admin:** [http://localhost:8000/admin/](http://localhost:8000/admin/)

---

### Вариант 2: Локальный запуск (Разработка)

#### 1. Backend (Django)
```bash
cd backend
python -m venv .venv
# Активация venv:
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt

# Применение миграций и наполнение демо-данными (>100 сотрудников)
python manage.py migrate
python manage.py seed_data

# Запуск сервера API
python manage.py runserver 127.0.0.1:8000
```

#### 2. Frontend (React + Vite)
```bash
cd frontend
npm install
npm run dev
```
Интерфейс доступен по адресу: [http://localhost:5173](http://localhost:5173).

#### 3. Desktop (Electron)
```bash
cd desktop
npm install
npm start
```

## 🧪 Автоматическое тестирование

В проект включен тестовый набор `pytest` (11 интеграционных и модульных тестов):

```bash
cd backend
pytest backend/tests
```

Тесты проверяют:
* Вычисление весов формулы алгоритма ($S$)
* Исключение кандидатов при конфликтах с отпусками
* Аутентификацию и выдачу JWT токенов
* Проверку разграничения прав доступа
* Запросы и мутации Strawberry GraphQL
